Core Principle

The framework follows a simple architectural rule:

Describe the UI first. Transform the description second. Create the DOM last.

JSON World and DOM World

JSON World
    |
    | specification transformations
    v
Resolved JSON
    |
    | materialization
    v
DOM World

Theme application, header visibility, body visibility, footer visibility, serial columns, and other structural changes happen before DOM creation.

The recursive DOM builder is the boundary between the JSON specification and the browser DOM.

The static skeleton establishes the component structure. Events connect behavior to that structure, while user data and dynamic UI are applied afterward.

Reusable Foundation

The deeper abstraction is not the Table itself. The reusable foundation is: 

Declarative Specification
        +
Composable Transformations
        +
Generic Recursive DOM Materialization

A Table is one consumer of this foundation. A Form can use the same underlying pipeline runner and recursive DOM construction mechanism.
