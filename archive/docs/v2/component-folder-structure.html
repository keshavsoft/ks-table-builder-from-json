Component Folder Structure

Organizing God JSON, Themes, transformations, renderers and component-specific code
Documentation Home Architecture God Spec Themes Theme Transformation Data Transformation Pipeline Execution Table Lifecycle Transformation Contract Component Composition

1. Purpose

This document describes a practical organization for keeping the different pieces of a specification-driven component together. 

Component
 |
 +-- God JSON
 +-- Themes
 +-- Pipeline
 +-- Columns
 +-- Renderers
 +-- Component code
 +-- Documentation
The folder should represent one component and contain the resources required to construct that component.

2. Component as a Folder

A component can have its own directory. 

table/

Everything specific to that Table can then live below it.

4. God JSON

The God JSON contains the structural specification for the component. 

table/
 |
 +-- god.json

It establishes the structural tree before dynamic transformations are applied.

5. Example God JSON

{
    "tagName": "div",

    "attributes": {
        "class": "table-wrapper"
    },

    "children": [

        {
            "tagName": "div",
            "attributes": {
                "class": "table-toolbar"
            }
        },

        {
            "tagName": "table",

            "children": [

                {
                    "tagName": "thead"
                },

                {
                    "tagName": "tbody",
                    "attributes": {
                        "slot": "body"
                    }
                }

            ]
        }

    ]
}

17. Component Entry Point

table/

The entry point can expose the component construction API.

18. Conceptual Entry Point

import godSpec from "./god.json";

const createTable = options => {

    const tasks =
        createPipeline(options);

    const finalSpec =
        runPipeline({
            inSpec: godSpec,
            inTasks: tasks
        });

    return buildDom({
        inSpec: finalSpec
    });

};

export {
    createTable
};

The exact implementation can differ; this illustrates the separation between specification, pipeline and DOM construction.

The folder structure should make the architecture discoverable.

For a Table, the God JSON is the structural foundation. Themes are kept as a related but separate presentation resource. Columns and renderers describe Table-specific behavior, while the pipeline composes those transformations.

The generic recursive DOM builder remains outside the Table folder because it is not Table-specific. It receives the completed specification and materializes it into DOM.

This gives the component a clean boundary: everything required to define and transform the Table stays together, while reusable infrastructure remains shared.
